# 验收合同 — No WiFi Games 合集

本合同是实现方提供的验收合同，目标是验证一个可离线打开的合集壳和任意一款小游戏的完整循环。

## 入口

- 构建目录：`build/web`
- 启动方式：静态服务器直接打开 `index.html`

## 第 1 层附加 · 可观测性要求（验收接口）

游戏启动后必须存在只读验收接口；接口不负责改变游戏状态。

| 接口 | 怎么调 | 何时可用 |
|---|---|---|
| 状态查询 | `window.__gameAcceptance.getState()` | 启动后任意时刻 |
| 配置查询 | `window.__gameAcceptance.getConfig()` | 启动后任意时刻 |

## 第 2 层 · 硬性达标线

| 名字 | 观测方式 | 合格带 |
|---|---|---|
| 就绪状态 | window.__gameAcceptance.getState().ready | true |
| 游戏数量 | window.__gameAcceptance.getConfig().catalog_size | = 14 |
| 离线标记 | window.__gameAcceptance.getConfig().offline | true |

## 第 3 层 · 完整循环的定义

1. 合集入口：看到 `NO WIFI GAMES` 和 14 张游戏卡片。
2. 做选择：点击任意游戏卡片，状态中的 `screen` 从 `home` 变为 `game`，并出现游戏标题。
3. 采取行动：使用方向键、数字键、点击或拖动完成一项有效输入。
4. 即时反馈：分数、步数、棋盘或角色状态发生可见变化。
5. 系统响应：继续操作直到胜利、失败或牌局结束状态可见。
6. 结算：出现“完成！”或“再试一次”结果覆盖层。
7. 回到开局：点击“重开”后状态回到 `playing`，棋盘恢复初始局面。

## 第 4 层 · 体验目标

短局、立即响应、无需登录和网络；颜色区分状态，触控区域足够大，玩家能理解下一步要做什么。每款游戏的规则差异应保留，但公共导航、重开和离线标记应保持一致。
